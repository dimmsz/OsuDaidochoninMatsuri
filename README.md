# 大須大道町人祭 NOW

第47回 大須大道町人祭（2026年10月9日～11日）を現地で使うためのPWAです。

「いま何が起きているか」を確認するNOW画面を中心に、タイムテーブル・会場・検索・お気に入り・出演者情報をまとめています。

## 基本構成

- フロントエンド: GitHub Pages / Azure Static Web Apps
- バックエンド・データ: Supabase
- 地図: Leaflet + OpenStreetMap
- 徒歩ルート: OpenStreetMap系のValhallaルートAPI
- PWA: Service Workerによるキャッシュ
- リポジトリ: `dimmsz/OsuDaidochoninMatsuri`

公開先:
- GitHub Pages
- Azure Static Web Apps: `https://orange-tree-05bc5d200.1.azurestaticapps.net`

## 画面構成

現在の基本ナビゲーションは5項目です。

1. NOW
2. タイムテーブル
3. 会場
4. 検索
5. お気に入り

出演者は6番目の下部ナビゲーションにはせず、独立した `performers.html` を用意しています。検索画面から出演者一覧へ移動でき、イベントカードから出演者詳細へ移動できます。

## NOW

現在時刻に基づいて、

- 開催中
- このあと
- 今日のタイムライン

を表示します。

## タイムテーブル

日付・会場で絞り込みできます。

「すべての日」を選択した場合は、各イベントカードに日付も表示します。

各イベントはカード形式で、

- 時刻・終了時刻
- 出演者
- 演目名
- 会場
- 会場区画
- ジャンル・タグ
- お気に入り

を表示します。

### 会場区画

公式タイムテーブルに合わせて、親会場と区画を分離しています。

たとえば大須観音は地図上では1つの会場ですが、タイムテーブルでは、

- 西門
- プロレス
- 中
- 東

を区別します。

DBでは `events.venue_id` を親会場、`events.venue_section` を区画として扱います。

同様に、裏門前町など、公式タイムテーブルで区分されている場所は区画として扱える構造にしています。

## 固定会場と移動型演目

「ロービング」は固定会場ではないため、`venues` に地図上の会場として登録しません。

イベントには、

- `location_type = fixed`: 固定会場
- `location_type = roaming`: ロービング
- `location_type = route`: パレード・行進などの移動型

を持たせています。

固定会場の場合:
- `venue_id` = 実際の会場
- `venue_section` = 会場内区画（必要な場合）

ロービング・移動型の場合:
- `venue_id` = NULL
- `location_label` = 「ロービング」など

画面上では、

- 固定会場: `📍 大須観音・東`
- ロービング: `🌀 ロービング`
- 移動型: `↔ 移動演目`

のように区別します。

## 会場・地図

地図は実在する固定会場だけを対象にします。

会場一覧の主な考え方:

> 物理的な場所 = venues  
> 会場内区画 = events.venue_section  
> 移動型の場所 = events.location_type / location_label

現在地から選択した会場までの徒歩ルート表示にも対応しています。

## 出演者マスター

出演者情報はイベントの文字列に直接埋め込まず、正規化しています。

主なテーブル:

### performers

出演者マスター。

- name
- official_url
- x_url
- instagram_url
- profile_url
- description
- genre
- source_url

公式サイトや公式SNSが確認できない場合は、無理にURLを埋めません。

### event_performers

イベントと出演者の多対多関係。

> event → 複数出演者  
> 出演者 → 複数イベント

を扱います。

イベント表記の例:

- `Cool-X／斎藤めぐ`
- `セ三味ストリート／チャタ／りずむらいす／idio2`
- `ダメじゃん小出／伊藤佑介／しょぎょーむじょーブラザーズ／ミコアポコ`

などを個別の出演者として紐付けています。

現在のデータは、出演者マスター59組、イベント→出演者リンク243件です。

## 出演者ページ

`performers.html` を独立した出演者ページとして実装しています。

機能:

- 出演者一覧
- 出演者名検索
- ジャンル検索
- 出演件数表示
- 出演者プロフィール
- 公式サイト / X / Instagram
- 出演スケジュール
- 出演スケジュールからのお気に入り登録
- **その出演者の出演を一括お気に入り登録 / 一括解除**

出演スケジュールはタイムテーブルと同じイベントカードを使用しているため、見た目・お気に入り状態を統一しています。

## お気に入り

お気に入りはブラウザの `localStorage` に保存しています。

キー:

`osu-favorites`

タイムテーブル、NOW、検索結果、出演者ページで共通利用します。

出演者ページでは、出演スケジュールの個別登録に加えて「一括お気に入り登録」ができます。

## 情報ソースの方針

情報の優先順位:

1. 祭り公式の全体資料・公式タイムテーブルPDF
2. 祭り公式サイト・公式告知
3. 出演者本人・団体の公式サイト
4. 出演者本人・団体の公式SNS
5. その他の二次情報

特に出演者のSNSは更新が早いため、公式・本人と確認できる場合は優先して登録します。

**公式情報が見つからないものは無理に埋めません。**

## 重要なデータ設計上の判断

### 出演者と演目を分離

タイムテーブルの「出演者」と「細かい演目」は同じ情報ではないため、イベントでは両方を保持します。

- `performer`: 出演者
- `title`: 演目名

画面では出演者を主表示、演目名を副表示にしています。

### 会場と会場区画を分離

大須観音のように「地図では1会場、タイムテーブルでは複数区画」という場所に対応するため、

- 親会場: `venues`
- 区画: `events.venue_section`

としています。

### 固定会場とロービングを分離

「ロービング」は公式PDF上では会場欄にありますが、固定地点ではないため、地図上の会場として扱いません。

`osu-now-v17`

## 開発メモ

現在は静的フロントエンドからSupabase Data APIを利用しています。

公開クライアントにはSupabaseのpublishable keyのみを使用し、service role keyは使用しません。

データ更新・スキーマ変更はSupabase側で行い、変更後はSQLで件数・関連付けなどを検証します。
